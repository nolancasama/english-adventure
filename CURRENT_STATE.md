# Current State

## Status

Playable storybook-styled MVP complete (2026-10-06). The full gameplay and persistence contract is unchanged; the visual layer now uses local illustrated assets, characters and responsive candy-depth UI. Not yet tested by a real child or on a physical Android device.

## What Exists

- Vite + React + TypeScript PWA (`vite-plugin-pwa`, Workbox precache, PNG + SVG icons). No backend; progress in localStorage (`mea.progress.v1`, versioned with migration).
- Content contract `src/content/types.ts`; data in `src/content/` (items, patterns, 10 lessons + chest milestone, pets). Review/Boss generated by `generate.ts` (weighted to missed/unseen items, shape-matched choices, abstract items excluded from picture questions).
- Activity registry `src/engine/activities.tsx`: listen-picture, picture-word, sentence-builder (tap tiles, lowercase display), speak (unscored).
- Screens in `src/App.tsx`: layered storybook home with a measured sandy road and on-road chest milestone; topic-tinted lesson/title/celebration flow; SVG Kiko and segmented-health Quiz Monster; pedestal pet collection; calm parent view behind a 3-second hold; reset with two confirmations; back-button guard.
- Audio `src/audio/`: recorded-file manifest (empty) → Web Speech fallback; WebAudio SFX.
- Typography is fully local: Fredoka Latin plus an app-specific M PLUS Rounded 1c Japanese WOFF2 subset (about 65 KB combined), both precached with `font-display: swap`.

## Art Assets

- Content and pet emoji use bundled Microsoft Fluent Emoji 3D artwork where available, with text emoji retained only as an explicit fallback.
- Regenerate the checked-in artwork and `src/art/emojiManifest.ts` with `node scripts/fetch-emoji-art.mjs`. This command needs network access and the `sharp` development dependency; neither is needed by the app at runtime or during a normal build.
- PWA SVG icons live in `public/icons/`. Regenerate their PNG and Apple touch-icon variants with `node .tmp/icons.mjs` after changing the SVG sources.
- The icon artwork features Kiko against the storybook sky and sandy hills. The maskable variant keeps Kiko and the adventure star inside the platform-safe central area.

## How to Run

```bash
npm install
npm run dev          # local dev
npm run build && npm run preview
npm run typecheck
npm test             # 34 unit tests
npm run e2e          # full 10-lesson playthrough at 320x640 (Playwright)
npm run e2e:shots    # one PNG per screen into .tmp/shots/
```

## Verification (2026-10-06 visual pass)

Observed locally after the correction pass: typecheck clean · 34/34 unit tests · build OK (67 precache entries, ~870 KB) · `npm run e2e` pass · `npm run e2e:shots` 3/3 (320x640 full set into `.tmp/shots/`, 390x844 and 768x1024 review sets into `.tmp/responsive-shots/`). The shots suite asserts every question picture lies inside its card; that guard was seen failing on the clipped-art bug and passing after the fix. Controller visual review of 320, 390 and 768 frames accepted.

Picture sizing note: picture cards, `.emoji-visual` and `.count-visual` use explicit `minmax(0, 1fr)` grid tracks so percentage heights resolve; without them the 192px art renders at intrinsic size and overflows. All art is preloaded at start-up (`src/main.tsx`) so cards never flash empty.

## Known Issues

- Glyphs without a matching Fluent Emoji asset use an explicit text-emoji fallback and may still differ slightly by platform.
- TTS voice quality/availability varies by device; no recorded audio yet.
- Japanese instruction speech uses ja-JP TTS only if the device has a Japanese voice.
- TTS and install-mode safe areas still need checking on the target Android device.
